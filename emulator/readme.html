ECEN 260 ARM32 Emulator Documentation (BYU-Idaho) [v1.5]

Overview

This ARM32 Assembly Emulator is a web-based tool designed to help students learn and practice ARM32 assembly programming. It supports a subset of ARM32 instructions, provides a visual representation of registers and memory, and includes support for conditional execution and memory operations.

Supported Instructions

The emulator supports the following ARM32 instructions:

  • MOV (Move)
  • MOVT (Move Top)
  • ADD (Add)
  • SUB (Subtract)
  • CMP (Compare)
  • MUL (Multiply)
  • SDIV (Signed Division)
  • UDIV (Unsigned Division)
  • AND (Bitwise AND)
  • ORR (Bitwise OR)
  • EOR (Bitwise XOR)
  • MVN (Bitwise NOT)
  • NEG (Negate)
  • LSL (Logical Shift Left)
  • LSR (Logical Shift Right)
  • ASR (Arithmetic Shift Right)
  • LDR (Load from Memory)
  • STR (Store to Memory)
  • LDRB (Load Register Byte)
  • LDRH (Load Register Halfword)
  • STRB (Store Register Byte)
  • STRH (Store Register Halfword)
  • B (Branch)
  • BL (Branch with Link)
  • BX (Branch and Exchange)
  • PUSH (Push onto Stack)
  • POP (Pop from Stack)
  • PRINT (Custom instruction for debugging)

Conditional Execution

The emulator supports conditional execution for almost all instructions. Conditions can be appended to instructions to control whether it executes based on the state of the APSR (Application Program Status Register) flags.

Some of the supported condition codes:

  • EQ: Equal (Z flag is set)
  • NE: Not Equal (Z flag is clear)
  • GT: Signed Greater Than (Z flag is clear AND N equals V)
  • GE: Signed Greater Than or Equal (N flag equals V flag)
  • LT: Signed Less Than (N flag is not equal to V flag)
  • LE: Signed Less Than or Equal (Z flag is set OR N is not equal to V)

Example usage:

ADDEQ R0, R1, R2  ; Add R1 and R2 into R0 only if the Z flag is set (i.e., the previous comparison was 'equal')
MOVNE R0, #0      ; Move 0 into R0 only if the Z flag is clear (i.e., the previous comparison was 'not equal')

Instruction Syntax and Examples

MOV (Move)

Moves a value into a register.

MOV R0, #10        ; Move decimal 10 to R0
MOV R1, R0         ; Copy value from R0 to R1
MOV R2, #0xFF      ; Move hexadecimal FF to R2
MOV R3, #0b1010    ; Move binary 1010 to R3
MOVS R4, #5        ; Move 5 to R4 and update flags
MOVEQ R5, #1       ; Move 1 to R5 if the Z flag is set (i.e., the previous comparison was 'equal')

MOVT (Move Top)

Moves a value into the top half of a register.

MOVT R0, #0xFFFF   ; Move 0xFFFF to top half of R0
MOVT R1, #0x123    ; Move 0x0123 to top half of R1

ADD (Add)

Adds two values and stores the result in a register.

ADD R0, R1, R2     ; R0 = R1 + R2
ADD R0, R0, #5     ; R0 = R0 + 5
ADD R1, #10        ; R1 = R1 + 10
ADDS R2, R3, R4    ; R2 = R3 + R4 and update flags
ADDNE R5, R6, #3   ; R5 = R6 + 3 if the Z flag is clear

SUB (Subtract)

Subtracts one value from another and stores the result in a register.

SUB R0, R1, R2     ; R0 = R1 - R2
SUB R0, R0, #5     ; R0 = R0 - 5
SUB R1, #10        ; R1 = R1 - 10
SUBS R2, R3, R4    ; R2 = R3 - R4 and update flags
SUBLT R5, R6, #3   ; R5 = R6 - 3 if N flag is not equal to V flag

CMP (Compare)

Compares two values and sets the condition flags in the APSR.

CMP R0, R1         ; Compare R0 with R1
CMP R0, #10        ; Compare R0 with 10

MUL (Multiply)

Multiplies two values and stores the result in a register.

MUL R0, R1, R2     ; R0 = R1 * R2
MULS R3, R4, R5    ; R3 = R4 * R5 and update flags

SDIV (Signed Division)

Performs signed division of two values and stores the result in a register.

SDIV R0, R1, R2    ; R0 = R1 / R2 (signed)
SDIV R3, R4, #5    ; R3 = R4 / 5 (signed)

UDIV (Unsigned Division)

Performs unsigned division of two values and stores the result in a register.

UDIV R0, R1, R2    ; R0 = R1 / R2 (unsigned)
UDIV R3, R4, #5    ; R3 = R4 / 5 (unsigned)

AND (Bitwise AND)

Performs a bitwise AND operation and stores the result in a register.

AND R0, R1, R2     ; R0 = R1 & R2
AND R0, R0, #0xF   ; R0 = R0 & 0xF
ANDS R3, R4, #0xFF ; R3 = R4 & 0xFF and update flags

ORR (Bitwise OR)

Performs a bitwise OR operation and stores the result in a register.

ORR R0, R1, R2     ; R0 = R1 | R2
ORR R0, R0, #0xF0  ; R0 = R0 | 0xF0
ORRS R3, R4, #0xFF ; R3 = R4 | 0xFF and update flags

EOR (Bitwise XOR)

Performs a bitwise XOR operation and stores the result in a register.

EOR R0, R1, R2     ; R0 = R1 ^ R2
EOR R0, R0, #0xFF  ; R0 = R0 ^ 0xFF
EORS R3, R4, #0xAA ; R3 = R4 ^ 0xAA and update flags

MVN (Bitwise NOT)

Performs a bitwise NOT operation and stores the result in a register.

MVN R0, R1         ; R0 = ~R1
MVN R0, #0xF       ; R0 = ~0xF

NEG (Negate)

Negates a value and stores the result in a register.

NEG R3, #4         ; R3 = -4
NEG R0, R1         ; R0 = -R1

LSL (Logical Shift Left)

Performs a logical left shift on a value.

LSL R0, R1, #2     ; R0 = R1 << 2 (shifted left by 2 bits)
LSL R0, R1, R2     ; R0 = R1 << R2 (shifted left by the value in R2)

LSR (Logical Shift Right)

Performs a logical right shift on a value.

LSR R0, R1, #2     ; R0 = R1 >> 2 (shifted right by 2 bits)
LSR R0, R1, R2     ; R0 = R1 >> R2 (shifted right by the value in R2)

ASR (Arithmetic Shift Right)

Performs an arithmetic right shift on a value.

ASR R0, R1, #2     ; R0 = R1 >> 2 (shifted right by 2 bits, preserving sign)
ASR R0, R1, R2     ; R0 = R1 >> R2 (shifted right by the value in R2, preserving sign)

LDR (Load from Memory)

LDR R2, [R0]       ; Load word from Memory at address R0 into R2
LDR R2, [R0, #4]   ; Load word from Memory at address R0+4 into R2
LDR R4, [R5, R6]   ; Load word from Memory at address R5+R6 into R4
LDR R7, [R8, #4]!  ; Pre-indexed: R8 = R8 + 4, then load word from Memory at new R8 into R7
LDR R9, [R10], #4  ; Post-indexed: Load word at R10 into R9, then R10 = R10 + 4

STR (Store to Memory)

Stores a value from a register into memory.

STR R0, [R1]       ; Store word in R0 to Memory at address in R1
STR R2, [R3, #8]   ; Store word in R2 to Memory at address R3+8
STR R4, [R5, R6]   ; Store word in R4 to Memory at address R5+R6
STR R7, [R8, #4]!  ; Pre-indexed: R8 = R8 + 4, then store word in R7 to Memory at new R8
STR R9, [R10], #4  ; Post-indexed: Store word in R9 to Memory at at address in R10, then update R10 = R10 + 4

LDRB (Load Register Byte)

Loads a byte from memory into a register.

LDRB R0, [R1]      ; Load byte at address in R1 into R0
LDRB R2, [R3, #1]  ; Load byte at address R3+1 into R2
LDRB R4, [R5, R6]  ; Load byte at address R5+R6 into R4

LDRH (Load Register Halfword)

Loads a halfword (16 bits) from memory into a register.

LDRH R0, [R1]      ; Load halfword at address in R1 into R0
LDRH R2, [R3, #2]  ; Load halfword at address R3+2 into R2
LDRH R4, [R5, R6]  ; Load halfword at address R5+R6 into R4

STRB (Store Register Byte)

Stores a byte from a register into memory.

STRB R0, [R1]      ; Store lowest byte of R0 to address in R1
STRB R2, [R3, #1]  ; Store lowest byte of R2 to address R3+1
STRB R4, [R5, R6]  ; Store lowest byte of R4 to address R5+R6

STRH (Store Register Halfword)

Stores a halfword (16 bits) from a register into memory.

STRH R0, [R1]      ; Store lowest halfword of R0 to address in R1
STRH R2, [R3, #2]  ; Store lowest halfword of R2 to address R3+2
STRH R4, [R5, R6]  ; Store lowest halfword of R4 to address R5+R6

B (Branch)

Branches to a specified label.

B label            ; Branch to label
BEQ label          ; Branch to label if equal (Z flag is set)
BNE label          ; Branch to label if not equal (Z flag is clear)
BLT label          ; Branch to label if less than (N flag is not equal to V flag)
BGT label          ; Branch to label if greater than (Z flag is clear AND N equals V)
BLE label          ; Branch to label if less than or equal (Z flag is set OR N is not equal to V)

BL (Branch with Link)

Branches to a specified label and stores the return address in LR.

BL subroutine      ; Branch to subroutine and store return address in LR

BX (Branch and Exchange)

Branches to the address specified in a register.

BX LR              ; Branch to the address stored in LR (typically used to return from a subroutine)

PUSH (Push onto Stack)

Pushes registers onto the stack. The registers are stored in order, with the lowest numbered register at the lowest memory address.

PUSH {R0}  ; Pushes the 4-byte contents of R0 onto the stack
PUSH {R4, R5, R6}  ; Push R4, R5, and R6 onto the stack (R4 at lowest address, R6 at highest)
PUSH {R0-R3, LR}   ; Push R0, R1, R2, R3, and LR onto the stack
PUSH {R0-R12, LR}  ; Push all general-purpose registers and LR onto the stack

POP (Pop from Stack)

Pops values from the stack into registers. The registers are loaded in order, with the lowest numbered register loaded from the lowest memory address.

POP {R0}  ; Pops the 4-byte value at the top of the stack into R0
POP {R4, R5, R6}   ; Pop values from stack into R4, R5, and R6 (R4 from lowest address, R6 from highest)
POP {R0-R3, PC}    ; Pop values from stack into R0, R1, R2, R3, and PC
POP {R0-R12, PC}   ; Pop values from stack into all general-purpose registers and PC

PRINT (Custom Instruction)

Prints the value of a register (not a standard ARM instruction, added for debugging).

PRINT R0           ; Print the value in R0

Stack Operations

The emulator implements a full, descending stack, following the ARM architecture:

  • The Stack Pointer (SP, R13) is initialized to 0x20018000.
  • The stack grows downwards in memory (from higher addresses to lower addresses).
  • PUSH decrements SP before storing each value.
  • POP loads each value and then increments SP.
  • Multiple registers can be pushed or popped in a single instruction.
  • Registers are stored/loaded in order, with the lowest numbered register at the lowest memory address within the relevant range.

Examples:

PUSH {R0, R1, R2}  ; Pushes R0, R1, R2 onto the stack (R0 at lowest address, R2 at highest)
POP {R0, R1, R2}   ; Pops values from stack into R0, R1, R2 (R0 from lowest address, R2 from highest)
PUSH {R0-R3, LR}   ; Pushes R0, R1, R2, R3, and LR onto the stack
POP {R0-R3, PC}    ; Pops values from stack into R0, R1, R2, R3, and PC

Immediate Values

The emulator supports immediate values in various formats:

  • Decimal: No prefix required
  • Hexadecimal: Can use '0x' prefix or 'h' suffix
  • Binary: Can use '0b' prefix or 'b' suffix

Examples of supported immediate value formats:

MOV R0, #42        ; Decimal
MOV R1, #0xFF      ; Hexadecimal with '0x' prefix (8-bit)
MOV R5, #0xFFFF    ; Hexadecimal with '0x' prefix (16-bit)
MOV R2, #FFFFh     ; Hexadecimal with 'h' suffix (16-bit)
MOV R3, #0b1010    ; Binary with '0b' prefix (4-bit)
MOV R6, #1010b     ; Binary with 'b' suffix (4-bit)
MOV R4, #11111111b ; Binary with 'b' suffix (8-bit)

Notes on immediate value usage:

  • For hexadecimal values, both uppercase and lowercase letters are supported (e.g., 0xFF and 0xff are equivalent).
  • The 'h' and 'b' suffixes must be immediately after the number, without any space.
  • When using the 'h' or 'b' suffix, do not include the '0x' or '0b' prefix.
  • The emulator will automatically handle sign extension for negative values when necessary.
  • For most instructions, immediate values are limited to 16 bits for MOV/MOVT and 12 bits for other instructions. The emulator will raise an error if the immediate value is out of range.

APSR (Application Program Status Register) (Continued)

These flags are updated by certain instructions (e.g., CMP) and are used for conditional execution. Instructions that can update the APSR flags typically have an 'S' suffix (e.g., ADDS, SUBS).

CMP R0, R1         ; Compare R0 and R1, updating APSR flags
ADDS R2, R3, #1    ; Add 1 to R3, store in R2, and update APSR flags
SUBS R4, R5, R6    ; Subtract R6 from R5, store in R4, and update APSR flags

Memory Layout

The emulator simulates two separate memory regions:

  • Code Memory: 0x00000000 - 0x00000100 (256 bytes)
  • Data Memory: 0x20000000 - 0x20018000 (not all bytes shown, just the top and bottom of the range)

Instructions are stored in Code Memory, while data operations typically use Data Memory.

Memory Indexing Options

The emulator supports various addressing modes for both load and store memory operations:

  • Offset addressing: [Rn, #offset]
  • Pre-indexed addressing: [Rn, #offset]!
  • Post-indexed addressing: [Rn], #offset
  • Register offset addressing: [Rn, Rm]
LDR R0, [R1, #4]   ; Offset addressing (use address R1+4)
LDR R0, [R1, #4]!  ; Pre-indexed addressing (use address R1+4, and change R1←R1+4)
LDR R0, [R1], #4   ; Post-indexed addressing (use address R1, then change R1←R1+4)
LDR R0, [R1, R2]   ; Register offset addressing (use address R1+R2)

Label Handling

The emulator now provides improved support for labels in your assembly code:

  • Labels can be defined on their own line or at the beginning of an instruction line.
  • Labels are automatically detected and mapped to their corresponding memory addresses.
  • Branch instructions (B, BL, BEQ, BNE, etc.) can use these labels as targets.
  • The emulator maintains an internal label map for efficient branching operations.

Example usage of labels:

loop:
    ADD R0, R0, #1
    CMP R0, #10
    BLT loop

end_loop:
    MOV R1, #0
    B end_loop  ; Infinite loop at the end

In this example, 'loop' and 'end_loop' are labels that can be used as branch targets.

Using the Link Register (LR) for Function Calling

The Link Register (LR), also known as R14, plays a crucial role in function calling and returning in ARM assembly. Understanding how to use the LR effectively is essential for writing and working with subroutines.

Function Calling Process

  1. When a function is called using the BL (Branch with Link) instruction, the address of the next instruction (return address) is automatically stored in the LR.
  2. The program then branches to the function's address.
  3. To return from the function, use the BX LR instruction, which branches to the address stored in the LR.

Example: Simple Function Call

    MOV R0, #5          ; Set up argument for the function
    BL calculate_square ; Call the function
    ; R0 now contains the result
    ; Continue with the main program

calculate_square:
    MUL R0, R0, R0      ; Square the input value
    BX LR               ; Return to the calling code

Nested Function Calls

When dealing with nested function calls, you need to preserve the LR value on the stack:

main:
    MOV R0, #5
    BL outer_function
    ; Continue with main program

outer_function:
    PUSH {LR}           ; Save LR on the stack
    BL inner_function   ; Call another function
    ; Do some work
    POP {PC}            ; Return by popping directly into PC

inner_function:
    ; Do some work
    BX LR               ; Return to outer_function

Best Practices

  • Always use BL for function calls and BX LR for returns to ensure proper use of the LR.
  • In functions that call other functions, preserve LR on the stack at the beginning and restore it before returning.
  • Be aware that some instructions (like BL) modify the LR, so save it if you need to preserve its value.
  • When using the PUSH and POP instructions with multiple registers, you can include LR in the list for convenient saving and restoring.

Value Pre-loading

  • Register Pre-Load: You can initialize registers with hexadecimal values up to 4 bytes before execution by entering values in the pre-load section. Format: R0: 0x10, SP: 0x20017FFC.
  • Memory Pre-Load: You can initialize data memory with 1-byte hexadecimal values before execution. Format: 0x20000000: 0x1234.

These enhancements make it easier to set up program conditions and test scenarios without manually stepping through initialization code.

Visual Cues for LR, PC, and SP

The emulator now provides visual indicators to help you quickly identify special registers and their values in both the register display and memory view:

  • Link Register (LR, R14):
    • In the register display: Highlighted with an orange border
    • In memory view: Memory locations containing the LR value are highlighted with an orange border
  • Program Counter (PC, R15):
    • In the register display: Highlighted with a yellow background
    • In code memory view: The current instruction (pointed to by PC) is highlighted with a yellow background
  • Stack Pointer (SP, R13):
    • In the register display: Highlighted with a purple border
    • In data memory view: The current top of the stack (pointed to by SP) is highlighted with a purple border

These visual cues make it easier to track the state of these important registers and their impact on program execution and memory state.

Usage Tips

  • Use the "Load Code" button to load your assembly code into the emulator.
  • The "Step" button allows you to execute one instruction at a time.
  • Use the "Reset Registers and Memory" button to clear all registers and memory.
  • The "Show Memory" toggle allows you to view or hide the memory display.
  • Use the memory display options to switch between 1-byte and 4-byte views, and to change the sorting order.
  • Pay attention to highlighted areas in the registers and memory displays, as they indicate recent changes.
  • Use the PRINT instruction to debug your code by printing register values.
